\# SmartCap Project Guide



\## Main objective

Help continue the existing SmartCap driver-monitoring project

without losing previous work or making unsupported assumptions.



\## Workflow



1\. Inspect the repository structure and README.

2\. Read the progress report and relevant project documentation.

3\. Identify the existing implementation before proposing changes.

4\. Trace how the relevant components interact.

5\. Separate confirmed facts from assumptions and unknowns.

6\. Identify the smallest useful next step.

7\. Explain the proposed changes before modifying files.

8\. Preserve existing interfaces and working functionality.

9\. Make only changes relevant to the requested task.

10\. Run available tests or checks after modifications.

11\. Report changed files, test results, limitations, and next steps.



\## Safety rules



\- Never invent hardware connections, sensor specifications,

&#x20; model performance, or completed features.

\- Never replace working code with a new implementation

&#x20; without understanding the current one.

\- Do not delete files or overwrite project documentation

&#x20; without explicit approval.

\- Do not commit, push, or change Git history without approval.

\- Do not expose credentials, tokens, or private configuration.



\## Expected response



For each task, provide:



1\. Current state based on repository evidence.

2\. Problem or requirement.

3\. Proposed implementation.

4\. Files to inspect or modify.

5\. Verification and test results.

6\. Remaining issues and next steps.
